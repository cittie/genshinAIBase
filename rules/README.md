# rules/ — AI 判定规则

本目录存放**决策方法**：给定事实与约束，如何得出推荐结论。

**边界**：这里只回答「该选哪个」，不重复解释机制（机制在 `docs/`），也不承载具体数值（数值在 `data/`）。

## 规则编写规范（强制）

一份合格的规则必须满足：

1. **可执行**：以「如果 … 那么 …」的判定形式表达，而非「视情况而定」。
2. **输入明确**：列出必须收集的参数；缺参数时给出默认值或要求追问。
3. **输出结构化**：固定输出模板（见各文件末尾），字段固定，便于比对。
4. **可解释**：每个结论都要能指向 `docs/` 的机制或 `data/` 的数值作为依据。
5. **带替代方案**：任何推荐都必须提供至少一个下位替代。
6. **声明前提**：命座、精炼、天赋等级、场景都要显式写出。
7. **容忍缺失**：数据缺失时明确说「未知」，并给出「在数据补齐前的保守建议」。

### 主观性的处理

强度排序、毕业标准等属**主观口径**。规则文件中必须：

- 显式声明「本规则采用的口径」（如「以 90 级、天赋 9-9-9、无命座、期望伤害为基准」）。
- 不把主观结论写成客观事实。
- 与 `docs/` 中的客观机制冲突时，以 `docs/` 为准并修正规则。

## 通用输出后缀

任何配队/配装建议输出时都要附上：

```
【前提】角色等级 / 天赋等级 / 命座 / 武器精炼 / 敌人假定
【依据】引用的文件路径
【数据缺口】本仓库未收录、影响结论的数值
【替代方案】至少一个下位替代及代价
```
