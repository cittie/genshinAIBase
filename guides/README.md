# guides/ — 攻略型内容

本目录存放**主观推荐**：把 `docs/` 的机制与 `data/` 的数值，落成「某角色/某队伍该怎么配」的方案。

---

## 与 data/ 的区别（重要）

| | `data/` | `guides/` |
|---|---|---|
| 性质 | 客观数值与枚举 | 主观推荐与取舍 |
| 可验证性 | 可对照游戏核对 | 取决于评分口径 |
| 时效 | 数值随版本变动 | 推荐随环境（深渊、新角色）变动 |
| AI 使用 | 直接引用 | 需**声明口径与版本**后引用 |

**因此每个 guide 文件必须带元信息头**（见模板），声明：

- 适用游戏版本
- 评分口径（等级 / 天赋 / 命座 / 精炼 / 敌人假定）
- 最后更新日期
- 数据可信度

## 目录

| 目录 | 内容 | 命名规则 |
|---|---|---|
| [character-builds/](character-builds/README.md) | 单角色配装方案 | `<slug>.md`，如 `hu_tao.md` |
| [team-comps/](team-comps/README.md) | 具体队伍方案 | `<archetype>__<主C slug>.md`，如 `vaporize__hu_tao.md` |
| [faq/](faq/README.md) | 常见问题 | `<topic>.md` |

模板文件以 `_` 开头（如 `_TEMPLATE.md`），**不视为正式攻略**。

---

## 写作要求

1. **必须带元信息头**（YAML frontmatter），否则视为无效文件。
2. **结论要给依据**：引用 `docs/` 的机制或 `data/` 的字段。
3. **必须给替代方案**，不能只给一个最优解。
4. **必须声明前提**（命座、精炼、天赋等级）。
5. **数据缺口要显式写出**：本仓库尚未收录的数值，不得用估计值填充。
6. 主观判断用「推荐 / 倾向 / 在 X 场景下更优」，不要写成客观事实。
