# 元素附着与 ICD

> 决定「反应能不能触发、能触发几次」的底层规则。
> 机读数值：[`data/elements/aura_consumption.csv`](../../data/elements/aura_consumption.csv)
> 来源：KQM Theorycrafting Library（固定 commit `106c0f3`），Elemental Gauge Theory。

## 1. 元素附着量（元素量）

攻击命中敌人时，若该攻击带有元素附着，会在敌人身上**叠加元素附着量**。

- 单位记作 **U**（Unit），`1U` 即 1 单位元素量。
- 附着量有**档位**之分，常见为「弱附着 / 强附着」，另有更高档位。
- 元素附着量**随时间衰减**（decay）：从附着瞬间起按一定速率减少，减到 0 时元素消失。

### 附着税（Aura Tax）

附着时先乘 **0.8×** 修正，再写入敌人身上：

| 攻击附着量 | 附着税后 |
|---|---|
| 1U | 0.8U |
| 1.5U | 1.2U |
| 2U | 1.6U |
| 4U | 3.2U |
| 8U | 6.4U |

> 风元素与岩元素**不能作为附着存在**（只能作为触发元素）。

### 衰减速率

衰减速率由**第一次附着的档位**决定，之后即使叠加更高的附着量也沿用该速率。

| 档位 | 衰减速率 |
|---|---|
| 1U | 11.875 秒 / 单位 |
| 1.5U | 8.9583 秒 / 单位 |
| 2U | 7.5 秒 / 单位 |
| 4U | 5.3125 秒 / 单位 |
| 8U | 4.21875 秒 / 单位 |

衰减速率公式（1 单位 = 25 点耐久）：

```
D(U) = 875 / (4 × 耐久) + 25 / 8
```

不做延长时，**附着的总时长 = 2.5 × 攻击附着量(GU) + 7 秒**。

> 3.0 起火元素附着的衰减速率更新规则与其他元素不同：仅当附着量真的发生变化时才更新速率。

### 关键推论

- 同一个攻击**是否带附着**比「打了几次」更重要：不带附着的攻击不产生元素、不触发反应。
- 附着量耗尽后，即使敌人仍在受伤，也不再触发元素反应。
- 高附着量的元素能支撑**多次**增幅反应（因为增幅反应只消耗部分附着量）。
- 若触发元素附着量大于被附着元素，反应仍会发生，被附着元素**被完全消耗**（附着量不会变成负数）。

## 2. 反应对附着量的消耗

| 反应 | 单位修正 | 说明 |
|---|---|---|
| 超载 / 超导 | **1×** | 等量消耗触发元素的附着量；两者的 **AoE 为零附着** |
| 增幅·弱（蒸发/融化 1.5 倍） | **0.5×** | 弱触发 |
| 增幅·强（蒸发/融化 2 倍） | **2×** | 强触发 |
| 扩散（Swirl） | **0.5×** | 风触发一律 0.5× |
| 结晶（Crystallize） | **0.5×** | 岩触发一律 0.5×；内建全局 ICD 1 秒（期间不再消耗附着） |
| 感电（Electro-Charged） | **0.4U / 跳** | 从水与雷**两个**附着量各扣 0.4U；AoE 跳为零附着 |
| 碎冰（Shattered） | **8U** | 常规消耗 8GU；部分情况下更少（可连续碎冰） |
| 绽放（Bloom） | 见备注 | 触发元素影响消耗，比例为水:草 = 2:1（水为弱元素），但**不影响伤害**；源未给出单一系数 |
| 冻结 / 燃烧 / 激化系 / 绽放系 | 见备注 | 源文档未给出可用的单一系数，详见 `data/elements/aura_consumption.csv` 的 `notes` |

> 完整机读表（含每条的来源链接）：[`data/elements/aura_consumption.csv`](../../data/elements/aura_consumption.csv)。
> 表中 `aura_consumed_ratio` 是**乘在触发元素附着量上的系数**，
> `aura_consumed_unit` 是**直接扣掉的固定 U 值**，两者互斥。

## 3. 反应优先级

当敌人身上附着某元素、而新的元素攻击命中时，若可触发多种反应，
游戏按**固定优先级**决定触发哪一个（例如火打冰附着优先走融化）。

- 优先级表是**游戏内置顺序**，不随版本大幅变动。
- 存在「元素共存」状态（如同时附着水与冰），此时可触发的反应集合不同。
- 存在「元素抵消」情况：一次攻击可能既触发反应又留下新的附着。

## 4. ICD（Internal Cooldown，内部冷却）

ICD 决定**同一套攻击序列中，哪些命中能附着元素**。

### 标准规则：2.5 秒 / 3 次命中

```
在同一个 ICD 组内：
  每 2.5 秒 重置一次计数
  或 累计 3 次命中 后重置计数
  两者取先到者
```

即：一个技能的第 1、2、3 次命中可附着，第 4 次不可；若期间过了 2.5 秒，计数重置后又可附着。

### ICD 组（组标签）

- 每个技能 / 每段攻击序列有**独立的 ICD 组**，不同技能之间互不影响。
- 因此「多段攻击」的实际附着次数需按各组分别计算。
- 常见模式：
  - **标准 2.5s/3 hits**：多数元素战技与爆发。
  - **无 ICD**：部分技能每次命中都附着（如某些持续输出型技能）。
  - **完全无附着**：部分攻击只造成伤害，不附着元素、不触发反应。
  - **每次命中附着但组独立**：多段技能各段独立计数组。

> ⚠️ **逐角色/逐技能的 ICD 组与附着标签表本仓库尚未收录**，
> 建议以 `data/characters/character_abilities.csv`（待建）承载。

## 5. 为什么这些规则重要

| 场景 | 受影响 |
|---|---|
| 判断「这套阵容能不能稳定触发蒸发」 | 附着量与 ICD 决定反应覆盖率 |
| 剧变反应队的伤害估算 | 附着量与反应消耗决定实际反应次数 |
| 扩散/聚怪队伍 | 扩散的传播规则决定实际命中数 |
| 持续输出角色的 DPS 估算 | 无 ICD 技能的反应覆盖率显著更高 |

**实务结论**：反应覆盖率（多少次伤害真正触发了反应）是配队评估中的关键变量，
不能假设「每一次伤害都触发反应」。

## 6. 数据缺失说明

本仓库**尚未收录**（全部标记为待核实）：

- 各附着档位的 U 值与持续秒数
- 各元素衰减速率
- 各反应的附着量消耗系数
- 反应优先级表
- 逐技能的 ICD 组与附着标签

> AI 使用要求：涉及上述内容时，必须声明「本仓库未收录该数值」，
> 可给出结构性结论（如「标准 ICD 为 2.5 秒 / 3 次命中」），
> 但**不得编造具体角色技能的附着次数或反应覆盖率**。
